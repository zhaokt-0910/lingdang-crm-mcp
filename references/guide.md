# 灵当CRM 配置向导 — 引导话术与排错手册

## 一、客户引导话术（AI 转述用）

### 连接账套成功时
> ✅ 账套「上海账套」已连接并验证通过（首页可达、登录接口正常）。
>
> 首次使用还需要两步：
> 1. 如果看到「信任」提示，请在连接器管理页对 `lingdang-crm-auth` 点一下「信任」——只需这一次，之后永久生效。
> 2. 请提供该账套的账号密码，我帮你登录后即可开始查询。

### 连接账套失败时
> ⚠️ 账套「上海账套」暂时连不上：{诊断详情}。
> 可能原因：{按诊断步骤解释}。请修正后我再试一次，或者我帮你逐级诊断（`diagnose`）。

### 客户问"之前连过哪些账套"时
> 已配置的账套有：{list_instances 结果}。告诉我账套名即可切换。

### 客户直接报账套名要查数据时
> 直接用 MCP 工具带 `instance=账套名` 查询，无需 Skill。若发现该账套未登录，引导提供账号密码后先 `login`。

## 二、常见错误排查

### 1. 首页访问失败 HTTP 404 / 403
- 原因：地址路径不完整。灵当CRM 通常部署在 `/crm` 路径下。
- 示例：客户给了 `http://192.168.1.100/`，实际应为 `http://192.168.1.100/crm`。
- 处理：提示客户确认完整访问地址（浏览器能打开 CRM 登录页的地址就是）。

### 2. 连接失败 Connection refused / timeout
- 原因：CRM 服务未启动，或端口未放行（防火墙/安全组）。
- 处理：让客户确认 CRM 服务在运行、端口对 WorkBuddy 所在机器开放。

### 3. 域名解析失败
- 原因：域名拼写错误，或内网 DNS 解析不到。
- 处理：核对域名；局域网场景建议直接用 IP。

### 4. 登录接口返回非 JSON
- 原因：该地址不是灵当CRM，或 PHP 端 `mcp_login.php` 未部署。
- 处理：确认已将 `crm_php_api` 下的 `mcp_login.php`、`modules/Mcp_auth_api.php`、`modules/Mcp_api.php` 部署到 CRM 的 `crmapi/` 目录。

### 5. 连接器已配置但 AI 说工具不可用
- 原因：连接器条目未启用，或本会话启动早于配置。
- 处理：连接器管理页启用 `lingdang-crm-auth`；必要时候重启会话。

### 6. 登录提示"用户名或密码错误"
- 原因：账号密码不对，或该用户在 CRM 中无登录权限。
- 处理：让客户在 CRM 网页端确认能正常登录；确认后重试。

### 7. 查询报"未登录或 session 已过期"
- 原因：24 小时 session 过期，或连接器重启。
- 处理：重新 `login(instance=账套名, ...)`。

## 三、给客户的安装前置条件（v4 零依赖，已大幅简化）

1. **Python 环境**：✅ **无需任何安装**。v4 运行层只依赖 Python 标准库（Python 3.8+），
   自动使用 WorkBuddy 内置 Python；旧版需要的 `mcp / httpx / pydantic-settings` 依赖已彻底移除。
2. **首次信任**：连接器条目写入 mcp.json 后，需在连接器管理页点一次「信任」。
3. **PHP 端部署**：CRM 服务器上需部署 `mcp_login.php` + `Mcp_auth_api.php` + `Mcp_api.php`（由实施方完成，客户无需操作）。

## 四、常见客户问法 → 动作映射

| 客户说 | 动作 |
|---|---|
| 连接我的 CRM，地址是 http://x/crm | `setup.py --name 账套名 --url ...` → 引导信任 → 引导登录 |
| 再加一个北京账套，http://y/crm | `setup.py --name 北京账套 --url ...` |
| CRM 连不上 | `diagnose.py --url ...` → 按步骤排查 |
| 有哪些账套 | `list_instances.py` |
| 查一下客户的电话 | MCP `query_module_data(instance=账套名, ...)`（不触发 Skill） |
